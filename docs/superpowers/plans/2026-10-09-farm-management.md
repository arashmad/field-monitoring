# Farm Management Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** An authenticated grower can create, list, view, and rename only their own Farms.

**Architecture:** Add a `farm` Drizzle table and migration. Server-only Farm operations obtain the owner from `requireCurrentUser()`, validate inputs, and constrain every query by both owner and Farm ID where applicable. Server actions adapt those operations for the protected Next.js UI; presentation components never import the database client.

**Tech Stack:** Next.js 16 App Router, React 19, TypeScript, Drizzle/PostgreSQL, Better Auth, Zod 4, Jest, Node test runner, Playwright.

**Spec:** [Issue #4](https://github.com/arashmad/field-monitoring/issues/4), [project plan](../../PLAN.md), [ownership contract](../../AUTHENTICATION.md), [architecture](../../ARCHITECTURE.md).

## Global Constraints

- Farm ownership is a single Better Auth `user.id`; no organizations or sharing.
- Farm data consists of an ID, owner ID, name, and creation/update timestamps. The issue specifies no other editable Farm attributes.
- Farm names are trimmed, required, and limited to 100 characters. This is an implementation choice because the issue does not set a limit.
- No Farm deletion, geometry, Fields, search, or pagination in this issue.
- Every data operation authenticates independently; the protected layout is not an authorization boundary.
- A missing Farm and another user's Farm produce the same not-found result.
- Use the existing migration workflow and the existing test database; tests create disposable users and clean them up.

## Review Focus

- Whitespace-only and overlong names produce field errors and never reach persistence (Task 1 and Task 3).
- A valid but foreign Farm ID gives the same result as an unknown ID for view and update (Task 2 and Task 4).
- A forged owner ID in submitted form data cannot change ownership (Task 2 and Task 4).
- An expired session cannot perform a write even if the protected page was previously rendered (Task 2 and Task 4).
- A concurrent owner-scoped update cannot change a Farm after ownership changes or target a different owner (Task 2).

### Task 2: Authenticated Farm operations

**Files:**
- Create: `features/farms/data.ts`
- Create: `features/farms/service.ts`
- Create: `tests/integration/farms.test.mts`
- Modify: `package.json`

**Interfaces:**
- Consumes: `farm`, `farmInputSchema`, `farmIdSchema`, `requireCurrentUser(requestHeaders?: Headers)`.
- Produces: `FarmRecord = { id: string; name: string; createdAt: Date; updatedAt: Date }` with no owner ID exposed to UI.
- Produces: `createFarm(input: unknown, requestHeaders?: Headers): Promise<FarmRecord>`, `listFarms(requestHeaders?: Headers): Promise<FarmRecord[]>`, `getFarm(id: unknown, requestHeaders?: Headers): Promise<FarmRecord | null>`, `updateFarm(id: unknown, input: unknown, requestHeaders?: Headers): Promise<FarmRecord | null>`.
- Produces: `FarmValidationError` carrying safe field errors; malformed input throws it. Missing or foreign IDs return `null` for single-Farm operations.

- [ ] **Step 1: Write real-database integration tests using two disposable provisioned users and their session headers.** Assert create assigns the session owner, list excludes the other owner's Farms and uses newest-first stable ordering, get returns own Farm, update changes own name/timestamp, and data functions return only safe fields.
- [ ] **Step 2: Add boundary tests.** Assert anonymous and expired sessions reject all four operations; whitespace/overlong names produce `FarmValidationError` without writes; malformed IDs are controlled; unknown and foreign IDs return indistinguishable `null`; submitted `ownerId` cannot redirect a create/update to another owner.
- [ ] **Step 3: Run `pnpm exec tsx --conditions=react-server --test tests/integration/farms.test.mts`.** Expect failure because Farm operations do not exist.
- [ ] **Step 4: Implement `features/farms/data.ts` as the only Farm database-access module.** Export internal owner-scoped insert/list/select/update helpers. Use `AND(farm.id = id, farm.ownerId = ownerId)` in the actual SELECT and UPDATE statements; update with `RETURNING` so a foreign or missing ID changes zero rows. Order lists by `createdAt DESC, id DESC`.
- [ ] **Step 5: Implement `features/farms/service.ts`.** Each public operation calls `requireCurrentUser()` itself, parses the ID/input, calls the data helper with `user.id`, and maps rows to `FarmRecord`. Do not accept an owner ID parameter from callers.
- [ ] **Step 6: Add `test:farms` to `package.json`, run it, and confirm all tests pass.** Ensure cleanup removes only test-owned users; cascading FK cleanup removes their Farms. Commit the server boundary.
